# Backend: auth, rate limiting, two-factor sign-in

Moved from `CLAUDE.md` section 6.2.

- **Auth, cookie, CORS**: one admin row, upserted at startup from `ADMIN_EMAIL` / `ADMIN_PASSWORD` (Argon2id via argon2-cffi with OWASP's baseline, m = 19 MiB, t = 2, p = 1: the library default takes 64 MiB per check, which a burst of logins would turn into an out-of-memory kill on the 1 GiB VM; always run in the thread pool with `run_in_threadpool` so a login never stalls the event loop; email lowercased). The startup upsert (`ensure_admin_user`) keeps exactly one admin: it deletes every other `admin_users` row (a previous `ADMIN_EMAIL` loses its password and its sessions), and when the configured password no longer verifies it re-hashes it and bumps `session_version`, revoking every session issued under the old password; a hash made with other parameters is re-hashed without revoking anything. `POST /auth/login` (`{email, password, turnstileToken}`) runs the IP limiter (which also bounds the calls to Cloudflare), then Turnstile (400 `turnstile_failed`, 503 `service_unavailable`; an attempt without a solved challenge neither reaches the password check nor counts toward the email limits, so the public admin email cannot be locked out with bogus tokens), then the email limiters, then waits up to 5 s for one of two password-check slots (`AppServices.password_checks`, an `asyncio.Semaphore`; a flood queues instead of exhausting memory, and a request that finds no slot gets 429 with `Retry-After: 5`), then a constant-time credential check (an unknown email verifies against a dummy hash computed at startup), and answers 401 `invalid_credentials` identically for unknown email and wrong password. Success sets `admin_session` = HS256 JWT (`sub` = user id, `email`, `ver` = the admin's `session_version`, `typ=admin_session`, `iat`, `exp` = 12 h) with `Path=/api; Max-Age=43200; HttpOnly; SameSite=Lax`, plus `Secure` when `APP_ENV=production`, no `Domain`; logout sends the same attributes with an empty value, `Max-Age=0` and `Expires` in 1970, and when the request still carries a valid session it bumps `session_version`, which revokes every copy of it (another tab or device, a leaked cookie). `GET /auth/me` and every admin route use the admin session dependency (`CurrentAdminDep` / `get_current_admin`; 401 `unauthorized` for a missing, invalid, expired, orphaned or revoked token: `ver` must equal the row's `session_version`); it commits after the lookup, so an upload's body is received without a pooled connection idle in a transaction. All of them answer with `Cache-Control: no-store` (the middleware above). CORS (`CORSMiddleware`): `CORS_ORIGINS` with credentials, `expose_headers=["ETag", "Retry-After"]`, `max_age=600`; the frontend sends `credentials: 'include'` only on `/auth/*` and `/admin/*`. CSRF protection, in layers: the SameSite=Lax cookie; exact CORS origins; `require_trusted_origin` on the `/auth` and `/admin` routers (a POST / PUT / PATCH / DELETE whose `Origin` header is present and not in `CORS_ORIGINS` is refused 403 `forbidden`; a request without `Origin`, such as curl, is left to the cookie check); JSON bodies (FastAPI reads a body as JSON only for `application/json`, so a `text/plain` or urlencoded form post fails validation); and uploads only on PUT, which no HTML form can send. Keep all four for every new mutating route. Client IP (`core/client_ip.py`): the rightmost `X-Forwarded-For` entry only when `TRUSTED_PROXY=true` (behind Caddy), otherwise the socket peer, otherwise the literal `unknown`; the raw IP stays in memory (rate-limit keys, Turnstile's `remoteip`); what is stored, emailed or logged is `hash_client_ip()`: HMAC-SHA256 keyed with `IP_HASH_SECRET` over the canonical address (IPv4-mapped IPv6 folded to IPv4), 64 hex characters, shown as its 12-character `fingerprint()` in emails and logs.

- **Rate limiting** (`core/rate_limit.py`): an in-memory sliding window per key (a deque of timestamps; rejected requests are not recorded; `Retry-After` = whole seconds until the oldest counted event leaves the window). A key's `<ip>` is `rate_limit_subject(ip)` (`core/client_ip.py`): the IPv4 address, or the /64 network of an IPv6 address (one subscriber usually holds a whole /64; behind Cloudflare visitors arrive over IPv6 too), while Turnstile and the stored hash keep the full address. Rules, every one counted on arrival (so a parallel burst cannot slip past a check made before its failure is recorded): `contact:ip:<ip>` 5 / 15 min before body validation (a dependency on the route), `login:ip:<ip>` 10 / 15 min, `login:email-ip:<email>:<ip>` 5 / 15 min (the brute-force limit) and `login:email:<email>` 30 / 15 min (a distributed guess), both cleared by a successful login (with two-factor sign-in on, only once the code step succeeds); `login:totp:<admin id>` 5 / 15 min and `login:totp-day:<admin id>` 20 / 24 h (authenticator codes; only someone with the password gets there; cleared on success) and `admin:reauth:<admin id>` 5 / 15 min (turning two-factor sign-in on or off). Each key is swept after its own rule's window. The admin email is public (it is the contact address), so failures from one address never lock the owner out elsewhere, and each attempt needs a solved Turnstile challenge. Two-factor sign-in (TOTP, `core/totp.py`, `services/totp.py`, `api/v1/admin_totp.py`, migration `0003_admin_totp`): RFC 6238 (HMAC-SHA1, 6 digits, 30 s, a 160-bit secret shown as base32; codes of the current step ± 1 accepted, and only for a step after `totp_last_counter`, so a code works once; ASCII digits only; the row is locked `FOR UPDATE` while a code is checked). The secret is stored encrypted (`SecretBox`: AES-256-GCM, key derived with HKDF-SHA256 from `TOTP_ENCRYPTION_KEY`, the admin id as associated data, `0x01 || nonce || ciphertext`), never in plain text, logs or responses after the setup. `admin_users` gains `totp_secret`, `totp_enabled_at` (a CHECK keeps them NULL together), `totp_last_counter` and `totp_pending_secret`. With it on, `POST /auth/login` answers `{email, totpRequired: true}` after the right password and sets no session but `admin_totp_pending` (a JWT with `typ=admin_totp_pending` and the admin's `session_version`, `Path=/api/v1/auth; Max-Age=300; HttpOnly; SameSite=Strict`, `Secure` in production; never accepted as a session); `POST /auth/login/totp` `{code}` (IP limit, then the pending cookie (401 `unauthorized` when missing, expired or revoked), then the code limits, then the code: 400 `totp_invalid`) clears it and sets the session; logout clears it too. Without it, `totpRequired` is false and login is one step as before. Admin routes (`/admin/totp`, the admin session, trusted origin, `no-store`): `GET` → `{enabled, enabledAt}`; `POST /setup` → `{secret, uri}` (a new pending secret, encrypted; 409 when already on); `POST /enable` and `POST /disable` `{password, code}` (re-authentication: the reauth limit, an Argon2 slot, 400 `wrong_password`; then 400 `totp_invalid`, 409 for the wrong state; `enable` checks a code from the pending secret, `disable` a fresh code from the active one); both bump `session_version` (every other session and pending sign-in revoked) and re-issue the caller's cookie. `GET /admin/summary` carries `totpEnabled`. An undecryptable secret (another key) is 503 `service_unavailable` and an error log, never a bypass. Recovery (a lost phone, a changed key): `python -m app.admin_totp reset` (on the VM, in `/opt/apps/anthonyzng-web`: `docker compose run --rm -T backend python -m app.admin_totp reset </dev/null`) turns it off and revokes every session; `status` reports it. Single-instance caveat: the counters live in one process, so run exactly one Uvicorn worker (Phase 4/6); several workers or replicas would each keep their own counters, and a shared store (Redis) is a later decision. Tests override `get_rate_limiter` and call `reset()`.
