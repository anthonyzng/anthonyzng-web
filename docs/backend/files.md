# Backend: files

Moved from `CLAUDE.md` section 6.2.

- **Files** (`models/stored_file.py`, `services/files.py`, `api/v1/files.py`; migration `0002_admin_panel`): uploads live in PostgreSQL, table `stored_files` (uuid id, `kind` `cv` | `project_image`, content type, original filename, size, sha256, width / height for images, `data` bytea loaded only when served; CHECKs on the kind, the sha256 format, `size = octet_length(data)` and the dimensions; a partial unique index admits one CV). `projects.image_id` references it (unique, `ON DELETE SET NULL`), and the placeholder CHECK also requires `image_id IS NULL`. A cover image is JPEG (including the MPF / "MPO" JPEGs of phones and cameras), PNG or WebP by its signature (anything else, garbage included, is 422 `file_type` before Pillow parses a byte) of at most 8 MiB and 40 megapixels (checked from the header, before decoding, with only the JPEG, PNG and WebP readers enabled, so no other format's parser ever runs on an upload); in the thread pool a JPEG is decoded at the smallest scale that still yields 1600 px after the camera's rotation (`draft`), then the image is turned upright from its EXIF orientation (malformed metadata is ignored, the pixels kept), 16-bit greyscale is scaled to 8 bits (a plain conversion would clip it to white), metadata is dropped but an RGB colour profile (Display P3, Adobe RGB) is kept, and it is scaled to fit 1600 px wide and 16383 px tall (WebP's limit per side) and stored as WebP (quality 82); anything Pillow cannot read or encode is a 422 `image_unreadable`, never a 500. The CV is one PDF (`%PDF-` signature) of at most 10 MiB; a new one replaces the old in one transaction under an advisory lock (`pg_advisory_xact_lock`), and its download name is the uploaded filename sanitised (no path, control or quote characters, `.pdf` ensured, at most 120 characters; `CV.pdf` by default). Replacing or removing an image, or deleting its project, deletes the old file; the project row is locked (`FOR UPDATE`) for it, so overlapping uploads replace each other in turn and leave no orphan. `GET /files/{id}`: 404 for a malformed or unknown id (the metadata is read on every request, so a removed file is gone at once); `ETag` = the sha256, 304 on `If-None-Match` without loading the body; the body comes from `FILE_BODY_CACHE` (an in-process LRU of 64 MiB: concurrent downloads share one copy, the database sends a body once) or the database; cover images `inline` with `Cache-Control: public, max-age=31536000, immutable` (a new upload always gets a new id), the CV (personal data) `attachment` with an ASCII `filename` and a UTF-8 `filename*` and `Cache-Control: private, no-cache` (no shared cache keeps it, a browser revalidates, so a removed CV stops being served).
