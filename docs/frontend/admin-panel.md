# Frontend: admin panel

Moved from `CLAUDE.md` section 6.1.

- **Admin panel** (`src/admin/`): its own lazy chunk for `/admin/*` (`App.tsx`), outside the smooth-scroll and language layouts; if the chunk fails to load (a stale chunk name after a deploy), the page reloads once, guarded by `sessionStorage['admin:reloaded']`; if it still fails, an `ErrorBoundary` shows `AdminLoadError` (public strings `adminLoad.*`) with a Reload button that clears the guard. Pages: `/admin` (dashboard: item counts, unread messages, the CV, a reminder while two-factor sign-in is off, how the built-in content copy is refreshed), `/admin/login`, `/admin/content/:collection` (list with move up / down, which posts a reorder, and delete behind a confirmation), `/admin/content/:collection/new` and `…/:slug` (the editor), `/admin/messages?status=unread&page=N` (inbox: read / unread, delete) and `/admin/cv` (upload, replace or remove the PDF). The login page carries the shared Turnstile widget: the submit is blocked (with a message on the widget, announced) until it has a token, the token is sent as `turnstileToken`, and any failed attempt (401, 400 `turnstile_failed`, 429 (seconds under a minute, else minutes), 503, network) resets the widget, since a token is single-use; a 422 keeps it unless it names `turnstileToken`. With two-factor sign-in on, a right password (`totpRequired: true`) swaps the form for the code step (`LoginCodeStep.tsx`): the Turnstile token is spent and the widget unmounts; one field (`control="otp"`: `inputmode=numeric`, `autocomplete=one-time-code`) takes focus; spaces are dropped (`totpCode.ts`) and exactly six ASCII digits are sent to `POST /auth/login/totp`; a wrong code (400 `totp_invalid`) empties and marks the field; a 401 (the 5-minute pending sign-in ran out or was revoked) and "Start again" return to the password step (a new challenge, the password field focused, the email kept); 429 / 503 / network have their messages. `/admin/security` (`SecurityPage.tsx`, nav "Security"): the status (on since …), "Set up" (`POST /admin/totp/setup`) shows the QR code (`QrCode.tsx`: `uqr`, one SVG path, dark on light in both themes, error correction M, a four-module quiet zone; only in the admin chunk) and the key in groups of four, then `TotpConfirmForm` (the password and a code) turns it on; when on, the same form turns it off; a wrong password or code marks and empties its field, a 409 (changed in another tab) reloads the status, 429 says when; after a change the section heading takes focus, the result is announced and the summary is refreshed (the dashboard reminder). The page names the shell reset for a lost phone. `RequireAuth` asks `GET /auth/me` once on entry; a 401 from any later call returns to the login page with the way back and a "session expired" notice. Every call goes through `src/admin/api.ts` → `requestJson` with `credentials: 'include'` (JSON bodies; uploads as `FormData` on PUT with a 120 s deadline), and responses are validated by `src/admin/schemas.ts`: JSON types only, so a row that breaks today's rules can still be opened and repaired, and non-strict objects, so a key the server adds later never flows back into a write. The editor is driven by the collection configs in `collections.ts` (fields, labels, hints, list title and detail) and checks the backend's limits before sending (`validation.ts`; lengths in code points, as Python counts them); Server answers are shown in the panel's own words, never the server's English: a 422 marks the control its dotted field names with "the server rejected this value" (`body` and keys that match no control become form-level errors, the latter with the path), a 409 lands on the slug, a 404 on save says the row was deleted elsewhere, a 413 says the entry is too large. The panel never sends `sortOrder` (the server places new rows and keeps the order on edits). An edit is saved with `If-Match: "<updatedAt>"`, the version it was loaded from (then of each save it stays on); a 412 keeps the changes on screen and in the tab and offers "Load latest version", which, after a confirmation, replaces the form with the server's row. The slug is fixed once created, and `new` is refused (it is the create route; the backend refuses it too). Cover images and the CV are saved at once, apart from the form (8 MB / 10 MB and the type checked before sending; one upload at a time: a pick made while one is on its way is refused, since aborting it would not stop the server); a refusal is shown by its `code` (the API surface list in `backend/CLAUDE.md`; an unknown one gets a generic "could not use this file"), a 413 as the size message. An image change leaves the project's `updatedAt` alone on the server, and the editor takes only the `image` from its answer (applied to the row as it is when the answer lands), so a change saved elsewhere meanwhile is still refused on save. Project links are checked like the backend does (the case-sensitive `http(s)://` prefix, a host without forbidden characters, a port from 1 to 65535, then the browser's parser). A placeholder project shows a note instead of the upload control. The inbox passes the first page's `asOf` to later pages (in the URL and the request), so paging through never shifts; page 1 and a filter switch start afresh (a refresh after a delete still passes the moment the page was taken at), and an out-of-range page or an `asOf` the API would refuse falls back to page 1. Unsaved drafts are kept per tab in `sessionStorage` (`admin:draft:<id>`, gone with the tab) and offered back after an expired session, a reload or Back / Forward; kept drafts are versioned (`{v: 1, …}`, other versions are ignored); in-app links, signing out and closing the tab ask before dropping changes, and the draft is dropped only once that action succeeded (a failed sign-out keeps everything) (Back / Forward cannot be guarded: the declarative router has no blocker). The page heading takes focus on every in-app navigation (not on Back / Forward); load errors are `role="alert"` with a Retry that moves focus to the heading and announces "Loaded." on success; a failed refresh keeps the loaded list with a notice. Strings live in the i18next namespace `admin` (`src/admin/locales/{en,zh-Hant}.json`, registered when the chunk loads, so none ship in the public bundle; `src/admin/locales.test.ts` checks key parity, placeholders, plurals, that Chinese is never a copy of the English and that every `t('…')` key exists). The language toggle shares `localStorage.lang` with the public site; dates use `zh-Hant-HK`. While mounted, the panel sets `<html lang>` and `<meta name="robots" content="noindex, nofollow">`. File URLs and sizes use the public helpers (`fileUrl`, `formatFileSize`). Tests (`src/admin/**/*.test.ts(x)`) run against a mocked API (`src/admin/test/mockApi.ts`, `fixtures.ts`; invented data only).
