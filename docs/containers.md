# Containers (Phase 6; on the Owwsolution platform since 2026-10)

Moved from `CLAUDE.md` section 6.3.

- **Platform**: the VM runs the Owwsolution platform (the private repo `Owwsolution/platform`, compose project `platform` in `/opt/platform`): Caddy, the only published service (80, 443, 443/udp); one PostgreSQL 17 instance shared by every app on the VM (one database and two roles per app); a nightly `pg_dump` per database. It gives this site two networks of its own, `edge-anthonyzng-web` and `db-anthonyzng-web` (internal, no route to the internet): Caddy and PostgreSQL join them, no other app does, and this stack joins no other app's, so no container of another Owwsolution app can open a connection to this site's containers (the platform's `deploy-app` refuses a compose file that names another platform network). This repo never runs a proxy or a database of its own in production. Apps on the platform talk to each other only through their public HTTPS URLs.

- **Stack** (`docker-compose.yml`, project `anthonyzng-web`, `/opt/apps/anthonyzng-web` on the VM): `backend` (waits for `migrate` completed successfully), `migrate` (the backend image, pulled by `deploy-app` or built by the local override's `backend` and never on its own (`pull_policy: never`), running `alembic upgrade head` as `anthonyzng_web_owner` once per `up`, then `python -m app.db_roles`, which takes `alembic_version` (and the other migration tool's bookkeeping table) away from the app role and checks that role's rights against the platform's allowlist, failing the deploy on any extra or missing one; `restart: "no"`), `frontend`. Images: `ghcr.io/anthonyzng/anthonyzng-web-{backend,frontend}:${IMAGE_TAG:-latest}` (CI pushes them, `docs/deployment.md`). The file has no `build` section (`deploy-app` never builds and refuses one); the local override adds them and tags the images `anthonyzng-web-{backend,frontend}:local`. Every service has `restart: unless-stopped`, `no-new-privileges`, `pids_limit: 200`, a read-only root filesystem (`/tmp` as tmpfs, except for `migrate`) and `cap_drop: [ALL]`. Memory caps (platform spec section 7): `migrate` 256 MB, `backend` 384 MB, `frontend` 64 MB. Networks: `edge` (`edge-anthonyzng-web`, created by the platform's `deploy-app` on the first deploy), where Caddy reaches the frontend and the backend under the aliases `anthonyzng-web-frontend` and `anthonyzng-web-backend` (the names the snippet uses); `db` (`db-anthonyzng-web`, created by `provision-app`), where the backend and `migrate` reach PostgreSQL as `platform-postgres`; the backend also keeps the project's default network for outbound HTTPS (Turnstile, Resend), its only route out. `deploy-app` checks the compose file before each deploy (an allowlist, `scripts/app_compose_check.py` in the platform repo): project `anthonyzng-web`, no `build`, no `ports`, no platform network but these two, on them no alias but `anthonyzng-web-<service>`, service names without hyphens, no `container_name`, and a `$variable` only inside `environment` values and `image` (the shared backend environment is the anchor `&backend-env` on `services.backend.environment`, merged into `migrate`; a top-level `x-` extension would be refused). It needs `backend/.env` (`env_file`, required) in the app directory. CI checks the service set and the absence of `build` and `ports` on every pull request (`docs/deployment.md`).

- **Database**: `anthonyzng_web` in the platform's instance, created with its roles and its network `db-anthonyzng-web` by the platform's `scripts/provision-app anthonyzng-web --scheme postgresql+asyncpg --write-env /opt/apps/anthonyzng-web/.env` (the server only receives SCRAM verifiers; the passwords go straight into `.env`). `anthonyzng_web_owner` owns the schema and only `migrate` connects as it; `anthonyzng_web_app` (the backend) gets `SELECT, INSERT, UPDATE, DELETE` on every table the owner creates through default privileges, `CONNECT` and `USAGE` on `public`, plus `USAGE` on the sequences and on the schemas the owner creates (the same default privileges; `app.db_roles` allows exactly this set), nothing else (no DDL, TRUNCATE, temporary tables, `alembic_version`, role creation or `COPY … PROGRAM`); `PUBLIC` has no right on the database, and neither role can connect to another app's database. Re-running provision-app rotates both passwords (then `docker compose up -d`). Configuration: the root `.env` (`DATABASE_OWNER_URL`, `DATABASE_APP_URL`, optionally `DATABASE_APP_USER`; `.env.example`) and `backend/.env` (the backend settings, loaded with `env_file`); the compose file sets the backend's `DATABASE_URL` from `DATABASE_APP_URL`, `migrate`'s from `DATABASE_OWNER_URL`, and `TRUSTED_PROXY=true`, overriding `backend/.env`; a missing URL stops `docker compose` with a message naming provision-app. `APP_ENV` is `production` unless the local override says otherwise (a `backend/.env` that lost that line cannot start with development defaults). The host-run backend keeps its own development database (`docker-compose.dev.yml`: project `anthonyzng-web-dev`, container `anthonyzng-web-db`, volume `anthonyzng-web_pgdata`, credentials `POSTGRES_*` in the root `.env`; its own project so that the site's `up --remove-orphans` never removes it; never `down -v`, which would delete the data). `docker compose config` prints the merged environment, secrets included: use `--quiet` to validate it.

- **Backend image** (`backend/Dockerfile`): `python:3.13-slim`; uv (`ghcr.io/astral-sh/uv:0.12`) installs the locked runtime dependencies only (`uv sync --frozen --no-dev --no-install-project`) into `/opt/venv`; the runtime stage copies the venv, `alembic.ini`, `alembic/` and `app/` (root-owned) and runs as the unprivileged `app` user (uid 10001). `CMD`: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1 --no-access-log --no-server-header --limit-concurrency 64` (one worker for the in-process rate limiter; no access log, which would record raw client IPs; beyond 64 requests in flight uvicorn answers 503 at once instead of queueing without bound). `HEALTHCHECK` calls `/api/v1/health`. `.dockerignore` keeps `.env`, `.venv`, `tests/` and caches out, so no secret is ever baked into an image. The same image runs the seed: `docker compose run --rm -T backend python -m app.seed </dev/null`.

- **Frontend image** (`frontend/Dockerfile`): `node:24.22.1-alpine` (the Active LTS, as in the workflows' `node-version`; pinned to the patch so a security release is a visible Dependabot bump, not a silent rebuild) runs `npm ci` and `npm run build` (typecheck + Vite) with the build args `VITE_API_BASE_URL` and `VITE_TURNSTILE_SITE_KEY` (both required: the build fails on an empty value instead of falling back to the development defaults of `src/env.ts`); the runtime is `nginxinc/nginx-unprivileged:1.31.7-alpine` (digest pinned; 1.31.7 fixes the October 2026 nginx advisories; the build upgrades its `brotli-libs` to the CVE-2026-111497 fix until the upstream image is rebuilt) on port 8080 with `frontend/nginx.conf`: `/assets/*` (hashed) `Cache-Control: public, max-age=31536000, immutable` and a 404 for a missing file, any other path with a file name (a dot in its last segment) that file or a 404 (a missing `/robots.txt` is never the app with a 200), every other path `index.html` (the SPA routes) with `no-cache`, `/healthz` for the healthcheck, gzip (`gzip_proxied any`: every request arrives through Caddy), `server_tokens off`, `absolute_redirect off`.

- **Proxy** (`deploy/anthonyzng-web.caddy`): the site's hosts on the platform's Caddy, installed into `/opt/platform/proxy/sites/` by the platform's `scripts/install-site` on every deploy, which validates the whole candidate config (the live Caddyfile and every app's snippet plus this one) with the live Caddy image and holds the snippet to the app's policy (only the addresses registered for this app with `scripts/app-hosts`, proxies only to `anthonyzng-web-<service>`, no file serving, no global options, no `import` but of the platform's `security_headers` and `to_backend` and of `anthonyzng_web_...` snippets defined in this file, `{$ANTHONYZNG_WEB_...}` values only, with plain defaults, no `{args...}` or `{block}` placeholder; checked on the text as Caddy reads it, with the platform's `caddy.env` spliced in) before the file reaches `sites/`, moves it in by an atomic rename and reloads Caddy (never a restart); an invalid or refused snippet is caught by `install-site --check` before anything starts and fails the deploy with nothing changed; the final install runs after `up`, and if its reload fails the previous snippet is put back and the deploy fails with the stack already up. The platform's Caddyfile holds the global options (Cloudflare's `trusted_proxies` with `client_ip_headers CF-Connecting-IP`, the server timeouts `read_header 10s`, `read_body 2m`, `write 2m`, `idle 2m`, no access log) and the shared snippets `security_headers` (HSTS one year, `nosniff`, no `Server`) and `to_backend` (`reverse_proxy` with `X-Forwarded-For` set to exactly `{client_ip}`, the rightmost entry the backend reads with `TRUSTED_PROXY=true`). The snippet: the site host with `X-Frame-Options: DENY` and CSP `frame-ancestors 'none'` (the admin panel can never be framed), `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` and the Content-Security-Policy (scripts only from the site, Cloudflare Turnstile (`challenges.cloudflare.com`, also the only `frame-src`) and Cloudflare Web Analytics (`static.cloudflareinsights.com`, beacons to `cloudflareinsights.com`), no inline script; styles only from the site; images and API calls from the site and the API origin; fonts from the site and `data:`; `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`); the `www` host redirecting permanently to the site URL; the API host (`default-src 'none'; img-src 'self'; frame-ancestors 'none'`, request bodies capped at 11 MiB, no compression, which would rewrite the ETags). Its addresses are Caddy placeholders with production defaults (`ANTHONYZNG_WEB_SITE_ADDRESS`, `…_SITE_URL`, `…_WWW_ADDRESS`, `…_API_ADDRESS`, `…_API_URL`, `…_SITE_EXTRA`), set only by a local platform's `caddy.env` (`deploy/local-caddy.env`); snippets it defines start with `anthonyzng_web_` (names are global on the platform). A new third-party script, frame, image or API origin needs its CSP entry here, checked in the browser console on the local stack. CI validates the snippet inside `deploy/ci/Caddyfile` (a copy of the platform's Caddyfile: keep it in step) with production's and the local addresses, and checks `caddy fmt`.

- **Locally**: a local platform (the platform repo checked out as `../platform`, its `.env` loading its `docker-compose.local.yml` after the generated override: Caddy on `127.0.0.1:8080` only, plain HTTP) with `deploy/local-caddy.env` as its `caddy.env`, this site's database, networks and registered addresses created there and its snippet installed (the `local-stack` skill, "Commands"); then `docker-compose.local.yml` (an override) adds the `build` sections (images tagged `:local`), sets `APP_ENV=development`, `CORS_ORIGINS=http://localhost:8080` and the frontend's local build args. Browsers take `localhost` and `api.localhost` for two different sites, so the admin's `SameSite=Lax` cookie would not reach `api.localhost`: the local build calls the API on the site's own origin (`VITE_API_BASE_URL=http://localhost:8080`), and `ANTHONYZNG_WEB_SITE_EXTRA=api` turns on the snippet's `/api/*` route on the site host (production has none).
